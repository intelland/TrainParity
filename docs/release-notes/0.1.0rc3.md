# TrainParity 0.1.0rc3 release notes

`0.1.0rc3` is a bounded bug-fix and onboarding prerelease following the
independent external integration of `0.1.0rc2`.

## Runtime fix

Ordinary user adapter failures in the command-oriented resume path now follow
the documented four-state contract. Exceptions raised by `command()`,
`checkpoint_path()`, or `observe_checkpoint()` produce a
`ProcessResumeResult` with `Outcome.ERROR` and identify the relevant execution
phase and callback boundary instead of unexpectedly escaping
`check_resume()`.

The boundary catches ordinary `Exception` values. `KeyboardInterrupt`,
`SystemExit`, and other `BaseException` subclasses are not wrapped as routine
`ERROR` results.

## External resume onboarding

The public documentation now defines the four stable execution phases:

- `baseline_a`;
- `baseline_b`;
- `candidate_split`;
- `candidate_resume`.

It also explains pre-launch checkpoint staging for `candidate_resume`, the
deterministic-location contract of `checkpoint_path()`, a wrapper pattern for
timestamped or implicit checkpoint paths, preserved child stdout/stderr under
an explicit `work_dir`, recommended semantically named observations, and the
cost of baseline self-consistency plus fresh-process execution. The complete
[external resume integration guide](../external-resume-integration.md) is
included in the source distribution.

Install this release candidate with:

```bash
pip install trainparity==0.1.0rc3
```

## Unchanged boundaries

This release adds no TrainParity check or framework adapter. It changes no
public API signature, comparison semantic, or `PASS` / `FAIL` / `ABSTAIN` /
`ERROR` definition. It does not expand PyTorch compatibility claims, infer
root causes, weaken baseline self-consistency, or relax the real
fresh-process resume boundary.
