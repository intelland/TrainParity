# TrainParity 0.1.0rc5 release notes

TrainParity 0.1.0rc5 is a bounded diagnostics and report-correctness prerelease
driven by independent external adoption of the public rc4 package.

Install the exact prerelease with:

```bash
pip install trainparity==0.1.0rc5
```

## Changes

- Accumulation setup `ERROR` results now retain the actionable wrapped cause
  while preserving the existing high-level boundary. When `report_path` is
  supplied, setup errors use the same deterministic report finalization path
  as other accumulation outcomes.
- Accumulation reports are published as exact UTF-8 bytes through the atomic
  temporary-file path. The returned `persisted_artifact_bytes`, the persisted
  JSON field, the filesystem size, and the actual payload length agree,
  including on Windows where text-mode newline translation previously made
  the values diverge.
- Sample coverage now distinguishes failures while advancing a rank iterable
  or DataLoader from failures in the sample-ID extractor callback and failures
  while consuming its output. Messages include the rank, attempted batch
  index, exception type, and exception text without dumping a traceback by
  default.

These changes came from bounded real-user cases involving accumulation and
sample-coverage adoption. They are evidence for the diagnosed interfaces, not
claims that any external project passes TrainParity in general.

## Unchanged boundaries

- No new check or Trainer/framework adapter was added.
- No DDP launcher or distributed-training orchestration was added.
- TrainParity does not infer root causes or numeric tolerances.
- Accumulation comparison semantics and sample-coverage policy semantics are
  unchanged.
- No broader Python, PyTorch, CUDA, GPU, or framework compatibility is claimed.
- The public machine-report schema remains version 2.
