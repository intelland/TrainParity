# TrainParity 0.1.0rc1 release notes

This alpha prerelease freezes three explicit PyTorch checks:

- checkpoint/resume equivalence across a real fresh-process boundary;
- user-declared gradient-accumulation equivalence at one optimizer update;
- finite sample-ID coverage with four explicit policies.

All machine reports carry schema version 1 and the package version. The public
surface is documented in the [public API reference](https://github.com/intelland/TrainParity/blob/main/docs/api.md); internal runners, snapshot backends,
experiments, Gate tooling, and accepted evidence are excluded from the stable
API and distribution payload.

The repository includes CPU quickstarts with clean and intentional-failure
results, conservative compatibility evidence, security guidance, and a release
audit. Install the exact candidate with `pip install trainparity==0.1.0rc1`.

Known limits include single-process training execution, exact full-value
snapshot costs, no framework adapters, user-declared observation completeness,
and finite-window-only sample coverage. See the [documented limitations](https://github.com/intelland/TrainParity/blob/main/docs/limitations.md) before use.

The release surface was subsequently hardened before publication: the
recommended top-level namespace contains only the three check entry points,
four coverage policies, exact and tolerance comparisons, `Outcome`, and
`__version__`; advanced adapter/result types remain in `trainparity.api`.
There is no v0.1 console-script entry point. GitHub Actions separates read-only
PR checks, manual/scheduled validation, and protected-environment OIDC
publication.
